# KeyTrail v1.4.0 — Linux port verification

Baseline: Windows-only v1.3.0, commit `916e25c`.

This version adds Linux browser/headless startup, XDG data paths, POSIX instance
locks and signal shutdown, Linux AES-256-GCM private-result protection, an
integrity-checked native CUDA build route, native ELF packaging, and Linux CI.
Windows WebView2/tray/DPAPI behavior remains on its existing platform path.

No real puzzle key is known and no real BTC is transferred.

## Executed local checks (2026-10-30)

- Windows Python 3.12.10: 72 tests, 52 executed successfully and 20 Linux-only
  tests skipped. Windows DPAPI and the offline payout self-test passed.
- Ubuntu 22.04 x86_64 under WSL2, Python 3.10.12, glibc 2.35: all 72 tests
  executed successfully. This includes real POSIX subprocess/PTY, stop/kill,
  kernel locking, AES-GCM tamper/key/permission checks and archive allowlisting.
- Source and frozen ELF HTTP smoke checks passed: local page serving,
  Host/Origin/token enforcement, duplicate instance reuse, Quit, restart from
  a synthetic checkpoint, SIGTERM and offline-only payout callbacks.
- The final CUDA archive was extracted to a different path and run as an
  ordinary (non-root) Linux user with LD_LIBRARY_PATH unset. GPU and offline
  payout self-tests passed; the key file was 0600. `ldd` resolved cudart from
  the extracted package, and `readelf` confirmed RUNPATH `$ORIGIN`.
- NVIDIA RTX 4070 Laptop GPU, driver 621.01, CUDA Toolkit 12.6.85: native
  BitCrack compiled at the pinned upstream revision. Real GPU self-tests
  recovered the already-public solved puzzle #20 answer. This was repeated
  with compute-75 cubin + PTX and a relocatable, bundled libcudart.so.12.
- Hardware stop/resume test on a bounded range not containing the public #20
  answer advanced confirmed cursors from 1,048,576 to 823,132,160 and then
  1,685,061,632. A separate complete one-quantum range ended exactly at its
  inclusive end + 1. No #71 search or Bitcoin broadcast was started.
- Maximum observed status output in that short GPU fixture was 478.85 MKey/s;
  this is not a sustained, cross-hardware or whole-puzzle benchmark.
- Windows Chrome rendered the Linux backend's real UI at 1440x1000 and
  390x844: Search/Ranges/Results, English/Chinese switching, hidden Windows
  window controls, no horizontal mobile overflow and no page errors passed.
  This is browser UI evidence against a Linux backend, not a native Linux
  desktop/browser certification. Screenshots are stored in `.test-output/`.
  Final screenshots show backend-derived v1.4.0 and the detected NVIDIA GPU.

## Issues found and fixed during validation

- Ubuntu's minimal OpenSSL configuration lacked hashlib RIPEMD-160. CPU search
  now uses embit's existing hash160 implementation and pure-Python fallback.
- Missing nvidia-smi telemetry no longer masks a successfully detected CUDA
  device; temperature protection still applies when telemetry is available.
- Upstream `make clean` removes a tracked OpenCL source input. The builder
  restores that exact pinned file and rejects any other source modification.
- Frozen executable verification accounts for PyInstaller's parent/child PID
  model; the actual per-directory instance lock remains kernel-enforced.
- The displayed UI version now comes from the backend instead of an old
  hard-coded v1.3.0 label.

## Acceptance boundaries

- Unit/process tests are not proof of NVIDIA hardware throughput.
- Headless HTTP smoke tests are not proof of interactive browser appearance.
- Offline/regtest transactions are not a mainnet receipt guarantee.
- Added CI configuration is not a completed GitHub Actions run.
- Linux x86_64/glibc coverage does not imply ARM64, musl or all distributions.
